# PLAN — identify the SDK on every API call via User-Agent (ClickUp 86e3c3akt)

Lane: feat/sdk-user-agent · sdk-go. Base `origin/main` @ `f3219d8` (v2.14.0 + one test-only
commit).

## Problem
No consumer/producer/agent request sent by this SDK identifies itself — every Helix API
call arrives at the server as the bare Go stdlib default (`Go-http-client/1.1`), so
server-side logs and the helix-api request parser can't attribute traffic to a specific
SDK build, language, or version.

## Contract
helix-api parses the FIRST token of `User-Agent` as `helix-sdk-<lang>/<semver>`. The value
must start with exactly `helix-sdk-go/<version>` (no leading `v`), matching:
`^helix-sdk-go/\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?( \(go/go[0-9.]+(rc\d+)?\))?$`. SigV4 must not
sign the header — verified against the pinned `aws-sdk-go-v2 v1.41.5` signer, which
hard-codes `User-Agent` into its `IgnoredHeaders` set (`signer/internal/v4/headers.go`), so
it can never join `SignedHeaders` regardless of header-set order relative to signing.

## Change
- New leaf package `internal/useragent` builds and caches
  `helix-sdk-go/<version> (go/<runtime>)`. Version resolution mirrors
  `consumer.resolveSDKVersion` (real resolved module version off the running binary's
  build info when available, falling back to a hardcoded default otherwise) — duplicated
  rather than imported/exported from `consumer/sdk_version.go`, since that file's edit
  scope is pinned to bumping `SDKVersion` per its own doc comment, not a refactor.
- `consumer.makeAPIRequest` and `producer.makeAPIRequest` — the single builder behind
  every Helix API call each package makes — set `User-Agent: <useragent.String()>` on
  every request, before signing (order is provably irrelevant per Contract above, but
  matches where `Content-Type` is already set).
- `agent.Client`'s default `userAgent` (previously an ad hoc
  `"helix-connect-sdk-go/agent"` const, overridable via `WithUserAgent`) is realigned
  to the same `useragent.String()` value for a consistent wire format across all three
  packages.
- Deliberately EXCLUDED: `consumer.DownloadDataset`'s presigned S3 GET and
  `producer.uploadToPresignedURL`'s presigned S3 PUT. Neither URL's signature is
  generated by this SDK, so there is no way to prove from this repo that decorating
  either request with an extra header is safe against however helix-api built the
  presigned URL's own `SignedHeaders`. Both exclusions are pinned by tests so a future
  change to either path has to consciously revisit this decision.
- `SDKVersion` (consumer.go) bumped 2.8.1 → 2.15.0 per its doc comment ("kept in
  lockstep with the latest module version tag as a best-effort default") — this is the
  fallback `internal/useragent` also uses.
